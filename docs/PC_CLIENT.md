# PC 端（Windows 电脑浏览器）

[English guide](PC_CLIENT.en.md)

PC 端让朋友在自己的 Windows 电脑浏览器里直接使用你电脑上的 DSH，而不是再做一个客户端应用：界面就是 DSH 自带的网页界面，由插件的移动访问网关提供。朋友不需要安装 DSH、Node.js 或任何客户端程序，只需要解压你发给他的一个小安装包。

| | 手机端 | PC 端 |
| --- | --- | --- |
| 客户端 | Android App 或手机浏览器 | 朋友的 Windows 电脑浏览器（Edge、Chrome 等） |
| 界面 | 专用触屏布局 | DSH 自带的桌面网页界面 |
| 安装 | 可选安装 APK | 解压安装包后运行启动脚本，无安装程序 |
| 定制层 | `mobile.css` / `mobile.js` | `desktop.css` / `desktop.js` |

PC 入口固定为 `<移动访问地址>/mobile-access/pc`，与配对窗口无关，随时可以打开；手机端的配对页面（`/mobile-access/pair`）只在配对窗口打开时存在。PC 端与手机端共用同一套设备配对、会话和撤销机制。

## 这是什么

- **不是第二个应用**：没有单独的 PC 客户端程序。打开的是同一份 DSH 网页界面，看到的是电脑上的同一份会话、工作区、消息和工具。
- **入口始终可用**：PC 入口页不依赖配对窗口，可以先打开页面、确认证书和安装步骤，再输入配对码。
- **可安装为桌面应用**：入口页提供 Web App Manifest 和一个只做直通、不缓存 DSH 内容的 Service Worker；浏览器支持时可以把它安装成独立窗口的桌面应用。
- **权限与手机相同**：配对后的 PC 和配对后的手机一样，是受信任的设备，可以操作电脑上的 DSH。

朋友的电脑必须能访问入口地址：局域网要求你和朋友在同一网络；朋友在外网时需要先开启远程通道。

## 电脑端：准备并分享

1. 在 DSH 左下角打开 **移动访问**，开启要使用的通道：**局域网**（朋友与你在同一网络时最简单）或 **远程**（朋友在外网时）。PC 端复用这两个通道，不新增监听端口。
2. 切换到 **PC 端** 标签页，页面会列出当前可用的入口地址（局域网与远程），并可直接复制。
3. 点击 **生成配对码**：这一步打开一个有时限的配对窗口（默认 5 分钟），显示配对码（应用密钥，形如 `dsh1.…` 或 `dsh2.…`）和可复制的 PC 入口链接。
4. 点击 **下载 PC 安装包**，得到 `dsh-mobile-pc.zip`；入口使用插件私有 CA 时，标签页还会给出证书下载链接和安装为桌面应用的简短说明。
5. 把安装包和配对码一起发给朋友。配对码是一次性凭据，默认 5 分钟内有效，被第一台设备成功使用后即失效；第二台设备或第二个浏览器需要重新生成。最省事的方式是直接发送 **PC 入口链接**：配对码就在链接的 `#` 片段里，朋友打开后不必手动输入。

> 安装包里没有任何密钥：只有说明、证书（需要时）和启动脚本。配对码请单独发送，不要写进文件名或长期保存。

入口是否需要证书取决于通道：cloudflared 命名隧道使用 Cloudflare 边缘证书，浏览器本来就信任，所以没有证书步骤；局域网和 SakuraFrp 自签入口使用插件自己的私有 CA，安装包里会附带证书和信任脚本。原因见[为什么还要安装证书](#为什么还要安装证书)。

## 朋友端：打开 PC 客户端

1. **解压**：把 `dsh-mobile-pc.zip` 解压到任意目录（例如桌面的 `dsh-mobile-pc`）。不要只打开压缩包里的单个文件：启动脚本需要和证书、说明放在同一目录。
2. **信任证书（仅在需要时）**：包里出现 `1-trust-certificate.cmd` 和 `dsh-mobile-ca.cer` 时，双击 `1-trust-certificate.cmd` 并按提示确认。它用 Windows 自带的 `certutil` 把证书安装到当前用户的“受信任的根证书颁发机构”，不需要管理员权限，也不改动系统其他设置。Windows 提示“已保护你的电脑”时选择“更多信息 → 仍要运行”；脚本报错时可以右键选择“以管理员身份运行”。使用公开受信任证书的远程入口没有这个文件，跳过这一步。
3. **运行启动器**：双击 `2-open-dsh.cmd`。找到 Edge 或 Chrome 时，它以应用窗口打开 PC 入口页；否则用系统默认浏览器打开。也可以双击 `open-dsh.url`，或直接在浏览器里打开入口地址。
4. **输入配对码**：入口页会先列出操作步骤，把配对码填进配对表单，可以给这台电脑起一个便于识别的设备名，然后提交。输入框接受三种写法：原始配对码、应用密钥（`dsh1.<实例>.<配对码>`）或整条 PC 入口链接（`https://…/mobile-access/pc#key=…`），直接粘贴链接最省事。配对成功后页面会跳到 DSH，浏览器会记住这台电脑；被拒绝时页面会说明原因（见下一节）。
5. **可选：安装为桌面应用**：入口页在浏览器支持时会显示 **安装为桌面应用** 按钮（也可以使用浏览器菜单里的“应用 → 将此站点作为应用安装”）。安装后会多一个桌面或开始菜单入口，打开时直接进入同一地址下的 DSH，不再经过入口页；它不会离线工作，电脑不在线时打不开。

只拿到入口链接、没有安装包时，也可以照常使用：在入口页上点击 **下载证书**（浏览器会先提示地址不安全，属正常现象），双击下载到的证书文件安装，然后关闭并重新打开该标签页，再输入配对码。

安装包内容：

| 文件 | 说明 |
| --- | --- |
| `README-zh.txt` / `README-en.txt` / `README-it.txt` | 上面的步骤说明，按下载安装包时浏览器的语言提供，UTF-8 编码 |
| `1-trust-certificate.cmd`、`dsh-mobile-ca.cer` | 仅在入口使用插件私有 CA 时提供 |
| `2-open-dsh.cmd` | 打开 PC 入口页，优先使用 Edge / Chrome 应用窗口 |
| `open-dsh.url` | 指向入口地址的 Internet 快捷方式 |

## 配对码为什么失效

- 配对码是一次性凭据：第一台设备成功配对后它就被消费掉，第二台设备，或同一台电脑上的第二个浏览器，都需要重新生成的配对码。
- 默认有效期是 5 分钟（插件配置项 `pairingTtlMs`，可设 10 秒到 15 分钟）。超过这个时间，配对窗口和配对码都会失效，但已经配对的设备不受影响。
- 输入框接受三种写法：原始配对码、应用密钥（`dsh1.<实例>.<配对码>`，自签远程入口为 `dsh2.…`）或整条 PC 入口链接。从面板复制的入口链接已经包含配对码，直接粘贴即可，不必手工截取。
- 配对被拒绝时页面会区分四种情况：
  - **配对码无效、已过期或已被使用**（401）：向电脑端索取新生成的配对码。
  - **网关拒绝了这次请求的来源**（403）：这不是配对码的问题；确认这台电脑和主机在同一局域网，或改用远程入口、使用正确的链接地址。
  - **尝试次数过多**（429）：稍等一会儿再试。
  - **配对窗口已关闭**（404）：向电脑端要一个新的配对码。

## 为什么还要安装证书

浏览器只信任自己认可的证书，所以要不要装证书，取决于这个入口出示的是谁的证书：

| 通道 | 公网入口出示的证书 | 是否需要安装证书 |
| --- | --- | --- |
| cloudflared 命名隧道 | Cloudflare 边缘证书，浏览器本来就信任 | 不需要，安装包里也不含证书 |
| SakuraFrp（仅支持 TCP 隧道） | 插件在本机用私有 CA 终结 TLS，浏览器看到的是这张自签证书 | 需要，安装包附带 `1-trust-certificate.cmd` 和 `dsh-mobile-ca.cer` |
| 局域网入口 | 同样是插件私有 CA | 需要，可从入口页或安装包安装 |

SakuraFrp 的公网入口形如 `https://<节点域名>:<端口>`：frp 节点自己的证书只覆盖它标准端口上的面板和域名，不覆盖隧道端口，所以这个地址上出示的是插件自签的证书，浏览器会先提示不安全。安装包里的 `1-trust-certificate.cmd` 就是为它准备的。

## PC 定制层

PC 端和手机端各有自己的定制文件，都放在 `$DSH_HOME/mobile-access/`：

| 客户端 | 样式 | 脚本 |
| --- | --- | --- |
| 触屏客户端（手机、平板） | `mobile.css` | `mobile.js` |
| 非触屏客户端（PC） | `desktop.css` | `desktop.js` |

- 网关通过 `/mobile-access/desktop.css` 和 `/mobile-access/desktop.js` 提供这两个文件，只有非触屏浏览器会加载；触屏浏览器仍然只加载 `mobile.css` / `mobile.js`。两层按客户端互斥，不会同时生效。
- 判定依据是浏览器报告的主输入方式（鼠标、触控板或触摸屏），不是操作系统：带触摸屏的 Windows 电脑，如果主输入被报告为鼠标或触控板，仍然使用 PC 层。
- 脚本用 `window.dshMobile.registerDesktop(({ document, window, request, root }) => cleanup)` 挂载 PC 专属内容：`root` 是挂载节点，`request(path, init)` 发起已认证的同源请求，返回的清理函数在重新加载或切换时调用。
- 保存 `desktop.css` 或 `desktop.js` 后，PC 页面会在几秒内自动应用，不需要重启 DSH；页面隐藏或连接断开时以定期检查兜底。删除这两个文件即恢复内置默认外观，不需要创建占位文件。
- 可以直接编辑这两个文件，也可以在 DSH 对话里用 `/mobile <需求>` 让 agent 修改同一目录；PC 定制不会影响手机层。
- 改动只放在 `$DSH_HOME/mobile-access/` 内，不要修改 DeepSeek Harness 源码。

## 安全边界

- **证书**：局域网入口和 SakuraFrp 自签入口使用插件自己的私有 CA，浏览器必须先信任它，否则会先看到“不安全”警告，也无法安装为桌面应用。安装包里的 `1-trust-certificate.cmd` 只把 `dsh-mobile-ca.cer` 装进当前用户的根证书存储，不写入系统范围，也不需要管理员权限。cloudflared 命名隧道使用 Cloudflare 边缘证书，不需要这一步，其配置见[命名隧道指南](CLOUDFLARE_TUNNEL.md)；各通道的差别见[为什么还要安装证书](#为什么还要安装证书)。
- **配对窗口很短**：点击“生成配对码”会打开一个一次性配对窗口（默认 5 分钟，可在插件配置中调整，范围 10 秒到 15 分钟）。窗口关闭后配对页面和配对码都失效，但已经配对的设备不受影响；配对码只能被成功使用一次，细节见[配对码为什么失效](#配对码为什么失效)。
- **配对码是凭据**：拿到配对码的人可以把自己的设备配对到你的 DSH。只把配对码发给你认识的人，并尽量单独发送；安装包里不含配对码。
- **PC 是受信任设备**：配对后的 PC 与手机一样可以操作电脑上的 DSH，应视为完全可信。朋友的电脑不再需要访问时，在电脑端 **移动访问** 里打开对应通道的已配对设备列表（局域网用 **管理配对设备**，远程用 **管理远程设备**）并撤销该设备；撤销会立即停止它的访问，旧令牌随后失效。
- **只在你开启时可达**：移动网关只在通道开启时监听；关闭局域网或远程通道后，已配对设备也无法连接。

更多背景见 [安全说明](../SECURITY.md)。

## 已知限制

- **启动脚本只针对 Windows**：安装包里的 `1-trust-certificate.cmd`、`2-open-dsh.cmd` 和 `open-dsh.url` 是 Windows 批处理与 Internet 快捷方式。macOS 或 Linux 朋友可以打开入口地址并使用浏览器，但证书信任和“应用窗口”需要手动完成，插件不提供对应脚本。
- **安装为桌面应用需要浏览器信任的 HTTPS**：Chromium 系的安装入口与 Service Worker 都要求安全上下文；证书未被信任，或直接忽略了证书警告时，不会出现安装按钮。想用桌面应用，请先完成证书信任，或改用公开受信任证书的远程入口。
- **不是离线应用**：安装后的桌面应用仍从你的电脑加载内容，不会缓存 DSH 页面；电脑离线、通道关闭或设备被撤销时无法使用。
- **Android App 不受影响**：PC 端不改变 App 的协议与配对流程，现有 App 配对无需重建，插件升级后 App 照常使用。
- PC 端不修改 DeepSeek Harness 源码，也不需要朋友安装 DSH 或 Node.js。
